# PRD 인터뷰

만들고 싶은 것: $ARGUMENTS

사용자와 인터뷰를 해서 이 폴더에 `PRD.md`를 만들어요. PRD는 무엇을 만들지 적은 요구사항 문서예요. 이 스킬은 코드를 만들지 않아요.

## 지킬 것

1. 질문은 AskUserQuestion 도구(질문 카드)로 해요. 카드 한 장에 질문 하나가 기본이에요. 짝이 되는 질문(예: name 칸과 message 칸의 이름표)만 한 장에 둘까지 넣어요.
2. 질문마다 머리말(header)은 12자 이내로 쓰고, 선택지는 2~4개를 줘요. 선택지마다 짧은 설명을 한 줄 붙여요. 가장 권하는 선택지는 맨 앞에 두고 이름 끝에 "(추천)"을 붙여요. 직접 쓰는 칸(Other)은 화면이 알아서 붙이니 선택지로 만들지 않아요.
3. 사용자가 이미 말한 것은 다시 묻지 않아요. 만들고 싶은 것에 주제가 들어 있으면 주제 질문은 건너뛰어요.
4. 질문 카드를 쓸 수 없으면 같은 질문을 글로 하나씩 하고, 번호를 붙인 선택지를 보여 줘요.
5. 질문은 모두 일곱 개 이하로 끝내요. 사용자가 "알아서 해"라고 하면 추천 선택지로 정하고, PRD의 그 줄 끝에 "(추천값으로 정함)"이라고 적어요.
6. 아래 '바꾸지 않는 약속'은 묻지 않고 PRD에 그대로 옮겨요. 사용자가 약속을 바꾸자고 하면, 수업의 확인 도구(smoke_test.py)가 이 약속으로 검사한다는 것을 알려 주고 화면 쪽에서 할 수 있는 방법을 제안해요.
7. 만드는 파일은 PRD.md 하나예요. 소스 코드, 설정 파일, 패키지 설치, 서버 실행은 하지 않아요. 화면, 서버, DB, 포트 같은 기술 선택은 다음 단계인 설계에서 정하니 묻지 않아요.

## 바꾸지 않는 약속

- `GET /api/entries`는 200과 `{"entries": [...]}`를 돌려줘요. 최신 글부터 최대 200개예요.
- `POST /api/entries`는 JSON 본문의 `name`과 `message`를 저장하고, 201과 `{"entry": {...}}`를 돌려줘요.
- 글 하나에는 `id`, `name`, `message`, `created_at`이 있어요. `created_at`은 UTC 시각의 ISO 문자열이에요.
- `name`은 앞뒤 공백을 지운 뒤 1~40자, `message`는 앞뒤 공백을 지운 뒤 1~500자예요. 문자열이 아니면 거절해요.
- 실패하면 `{"error": "설명"}`으로 답해요. 잘못된 값과 깨진 JSON은 400, 8KiB가 넘는 본문은 413, JSON이 아닌 형식은 415, 없는 주소는 404예요.
- JSON 키 `name`과 `message`는 바꾸지 않아요. 화면에 보이는 이름표만 주제에 맞게 바꿔요.
- 주제에 맞는 칸을 더할 때는 선택 칸으로만 더해요. 그 칸이 비어 있거나 없어도 201로 저장돼야 해요. 더하는 칸의 JSON 키는 짧은 영어 소문자로 정해요(예: `to`, `tag`).

## 물어볼 것

필요한 것만 이 순서로 물어요.

| 순서 | 머리말 | 질문 | 선택지 예 |
| --- | --- | --- | --- |
| 1 | 주제 | 무엇을 남기는 게시판인가요? | 팀 회식 방명록, 칭찬 릴레이, 장애 회고 게시판 |
| 2 | 쓰는 사람 | 누가 글을 남기고 보나요? | 우리 팀(로그인 없음), 회사 여러 부서, 행사 손님 |
| 3 | 칸 이름 | name 칸과 message 칸을 화면에서 뭐라고 부를까요? | 주제에 맞는 이름표를 칸마다 2~3개 |
| 4 | 더할 칸 | 주제에 맞게 선택 칸을 더할까요? | 더하지 않기, 주제에 맞는 칸 한두 개 |
| 5 | 목록 모양 | 목록은 어떤 모양으로 보일까요? | 카드, 한 줄 목록, 말풍선 |
| 6 | 분위기 | 화면 분위기는 어떻게 할까요? | 깔끔한 업무용, 밝고 가벼운 느낌, 회사 색 |
| 7 | 빼는 것 | 이번에 하지 않을 것을 골라 주세요. | 로그인, 수정·삭제, 페이지 나누기, 검색 |

- 3번은 name 칸과 message 칸을 한 카드에 질문 두 개로 물어도 돼요.
- 4번과 7번은 여러 개를 고를 수 있게(multiSelect) 물어요. 7번은 네 개 모두를 추천해요.
- 목록이 최신 글부터 보이고 최대 200개라는 것은 약속이라 묻지 않아요.

## PRD.md 모양

짧은 해요체 문장으로 써요. 제목과 순서는 아래를 따라요. 괄호 안은 인터뷰에서 정한 것으로 바꿔요.

```markdown
# PRD · (주제)

## 목적
- (무엇을 남기고 누가 보는지 한 문장)

## 쓰는 사람
- (누가, 몇 명쯤, 로그인 여부)

## 화면
- 입력: (name 이름표)(name), (message 이름표)(message), (더한 칸이 있으면 이름표와 키)
- 목록: (모양), 최신 글이 맨 위
- 분위기: (고른 것)
- 저장하는 동안 버튼을 막고, 서버 오류는 화면에 문장으로 보여 줘요.
- 사용자가 쓴 글은 글자 그대로 보여 줘요. HTML로 넣지 않아요.

## API 약속 (바꾸지 않음)
| 요청 | 성공 응답 | 내용 |
| --- | --- | --- |
| GET /api/entries | 200, {"entries": [...]} | 최신 글부터 최대 200개 |
| POST /api/entries | 201, {"entry": {...}} | JSON 본문의 name, message를 저장 |
- 글 하나에는 id, name, message, created_at(UTC ISO 문자열)이 있어요.
- name은 앞뒤 공백을 지운 뒤 1~40자, message는 앞뒤 공백을 지운 뒤 1~500자예요. 문자열이 아니면 거절해요.
- 실패하면 {"error": "설명"}으로 답해요. 잘못된 값과 깨진 JSON은 400, 8KiB가 넘는 본문은 413, JSON이 아닌 형식은 415, 없는 주소는 404예요.

## 더한 칸 (선택)
- (이름표)(키): (설명). 비어 있거나 없어도 저장돼요.

## 확인
- 공통 확인 도구: python3 ~/dbinc-ai-course/labs/guestbook/smoke_test.py --url (설계에서 정한 서버 주소, 기본 http://127.0.0.1:8080)
- 브라우저: 글을 저장하고, 새로고침하고, 서버를 다시 켠 뒤에도 글이 남는지 봐요.

## 이번에 하지 않는 것
- (고른 것)
```

- 더한 칸이 없으면 '더한 칸' 절에 "없음"이라고 적어요.
- 수업 저장소를 다른 곳에 받았으면 확인 도구 경로를 그 자리로 바꿔요. Python 표준 라이브러리로 만드는 길이면 확인 줄을 `python3 ~/dbinc-ai-course/labs/guestbook/smoke_test.py --app app.py`로 써요.

## 마무리

- Plan 모드에서 불렸다면, 인터뷰가 끝난 뒤 PRD.md에 쓸 내용 전체를 계획으로 내놓아요. 사용자가 승인하면 PRD.md 한 파일만 쓰고 멈춰요.
- Plan 모드가 아니면, PRD.md 내용을 먼저 보여 주고 "이대로 쓸까요?"를 질문 카드로 물어요. 승인하면 그때 써요.
- 다 쓰면 바뀐 파일이 PRD.md 하나인지 확인하고, 다음 할 일을 한 문장으로 알려 줘요. 예: "새 세션에서 Plan 모드로 설계를 받아 보세요."
